## 技术选型

| 项 | 选择 | 理由 |
| --- | --- | --- |
| 语言 | Python 3.11+（开发环境 3.14） | 课程已学，标准库能力足够 |
| Web 服务 | `http.server.ThreadingHTTPServer` | 机房断网、不装第三方包也能跑 |
| 数据库 | SQLite 3（`sqlite3` 标准库） | 单文件、免安装，便于随仓库演示 |
| 口令安全 | `hashlib.pbkdf2_hmac`（SHA-256，120000 轮，16 字节盐） | 满足课程"口令加密存储"底线要求 |
| 会话 | `secrets.token_urlsafe(32)` + HttpOnly Cookie | 30 分钟不活跃自动过期 |
| 测试 | `unittest` | 无第三方依赖，`python test/run_tests.py` 一键执行 |

`requirements.txt` 中不含任何第三方依赖，克隆后即可运行。

## 目录结构

```
library-system/
├── src/
│   ├── app.py                  # HTTP 服务入口与路由分发
│   ├── config.py               # 全局配置（会话、借阅、罚款参数）
│   ├── common/                 # 公共工具：安全、校验、日志
│   ├── controller/             # 控制器层：请求解析与响应组装
│   ├── service/                # 业务逻辑层：注册、登录、注销
│   ├── dao/                    # 数据访问层：账号与会话的 SQL
│   ├── db/                     # 建表脚本 schema.sql、连接封装、初始化脚本
│   └── web/                    # 页面模板与静态资源
├── docs/
│   ├── 需求规格说明书.md        # SRS（LIB-SRS-001）
│   ├── 数据库设计.md            # E-R 描述与字段说明（LIB-DB-001）
│   ├── 迭代计划.md              # 三轮迭代安排与迭代一任务清单
│   └── uml/img/                # 五张需求分析图（png）
├── test/                       # 29 条测试用例
├── data/                       # 运行时生成的 library.db（不提交）
├── logs/                       # 业务日志（不提交）
├── start.py                    # 启动脚本
└── README.md
```

分层依赖方向：`controller → service → dao → db`，`common` 被各层调用，反向依赖一律不允许。

## 运行方式

```bash
# 1) 初始化数据库（建表 + 演示账号 + 示例分类）
python -m src.db.init_db

# 2) 启动服务（默认 http://127.0.0.1:8000）
python start.py

# 也可以用模块方式启动，或指定端口（第一个参数即端口）
python -m src.app
python start.py 8080
```

浏览器打开 `http://127.0.0.1:8000/login` 即可。

## 迭代一已实现的内容

1. 11 张基础表的建表脚本：账号、读者档案、会话、业务日志、分类、书目、复本、借阅记录、预约、罚款、通知；
2. 数据库连接封装：统一开启外键约束、Row 工厂、上下文内提交与回滚；
3. 读者自助注册：登录名 / 真实姓名 / 手机号 / 口令四类校验，弱口令拒绝，登录名唯一；
4. 登录与注销：口令散列比对（常量时间比较），连续 5 次失败锁定 15 分钟，冻结账号拒绝登录，会话 30 分钟过期；
5. 会话鉴权：HttpOnly Cookie 携带令牌，未登录访问受保护页面返回 401 并按角色跳转；
6. 业务操作日志：注册、登录、登录失败、注销写入 `sys_audit_log`，同时落 `logs/business.log`；
7. 登录、注册、主页三个页面（浅绿主题，响应式宽度）；
8. 29 条测试用例：口令安全、注册登录业务分支、接口层鉴权。
