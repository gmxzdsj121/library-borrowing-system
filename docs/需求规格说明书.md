## 1 引言

本文档给出图书借阅管理系统迭代一的完整需求，包括参与者、功能性需求、非功能性需求、用例模型与需求分析模型。编号规则：功能需求 FR-××，非功能需求 NFR-××，用例 UC-××。编号在迭代二、迭代三中保持不变，测试用例与缺陷记录均按此编号追溯。

## 2 系统总体描述

### 2.1 利益相关方与诉求

| 利益相关方 | 核心诉求 |
| --- | --- |
| 读者用户 | 快速检索、自助查看借阅与到期、在线续借与预约、罚款金额透明 |
| 图书馆管理员 | 借还办理快、馆藏复本状态准确、读者档案与罚款收取有据可依 |
| 审核统计管理员 | 注册账号有人把关、权限可控、罚款减免可审批留痕、报表支撑月度汇报 |
| 系统维护者（组内兼任） | 部署简单、日志可查、故障可定位 |
| 管理部门（模拟） | 借阅量、逾期率等数据可信，可支撑采购与考核 |

### 2.2 参与者（3 类）

| 编号 | 参与者 | 职责范围 |
| --- | --- | --- |
| A1 | 读者用户 | 注册登录、检索、续借、预约、查询本人借阅与罚款 |
| A2 | 图书馆管理员 | 图书与复本维护、借阅登记、归还处理、罚款收取、读者档案 |
| A3 | 审核统计管理员 | 账号审核、角色权限配置、罚款减免审批、统计报表、通知公告 |

### 2.3 系统边界与运行环境

- 结构：浏览器/服务器（B/S），可单机部署于一台办公电脑。
- 服务端：Python 3.11+，仅使用标准库（http.server、sqlite3、hashlib、logging、unittest）。
- 数据库：SQLite 单文件库，开启外键约束。
- 客户端：Chrome / Edge / Firefox 最近两个大版本，最小分辨率 1366×768。
- 外部系统：校园统一身份认证（迭代三接入）、短信/邮件通知服务（迭代三接入，迭代一以站内消息占位）。

## 3 功能性需求

| FR 编号 | 功能模块 | 功能项 | 功能描述 | 优先级 |
| --- | --- | --- | --- | --- |
| FR-01 | 用户与账号管理 | 用户注册与登录 | 读者自助注册；口令 PBKDF2 加盐散列存储；登录颁发会话令牌；连续 5 次失败锁定 15 分钟；冻结账号禁止登录 | 高 |
| FR-02 | 用户与账号管理 | 账号审核与权限管理 | 审核新注册账号（通过/驳回/冻结），创建馆员账号并分配角色，查看账号审计 | 高 |
| FR-03 | 图书与馆藏管理 | 图书信息维护 | 维护 ISBN、书名、作者、出版社、分类、单价；同一 ISBN 唯一 | 高 |
| FR-04 | 图书与馆藏管理 | 馆藏复本管理 | 按条码管理复本与状态（在架/借出/预约保留/遗失/维修），状态随业务流转 | 高 |
| FR-05 | 图书与馆藏管理 | 图书检索 | 书名/作者/ISBN/分类模糊检索，返回复本可借状态，分页，≤2s | 高 |
| FR-06 | 借阅服务 | 借阅登记 | 校验读者资格与复本可借后写入借阅记录，应还日期 = 借出日 + 30 天 | 高 |
| FR-07 | 借阅服务 | 归还处理 | 计算逾期天数，超出 3 天宽限期按 0.5 元/天生成罚款单；复本回架或转预约保留 | 高 |
| FR-08 | 借阅服务 | 续借 | 每条记录最多 2 次，每次顺延 30 天；逾期或被预约时禁止 | 中 |
| FR-09 | 借阅服务 | 预约借书 | 无可借复本时可预约，FIFO 排队；到书保留 3 天，超期顺延 | 中 |
| FR-10 | 罚款与信用 | 逾期罚款管理 | 罚款生成、缴纳登记、减免审批留痕；未结清暂停借阅与预约 | 高 |
| FR-11 | 读者服务 | 读者档案管理 | 读者证号、类型、借阅上限、信用分；冻结/解冻；信用分<60 限制预约 | 中 |
| FR-12 | 统计与通知 | 借阅统计报表 | 按日/月/分类/读者类型统计借阅量、归还率、逾期率、罚款金额，导出 CSV | 中 |
| FR-13 | 统计与通知 | 通知与公告 | 到期前 3 天提醒、到书通知、罚款通知、公告发布 | 低 |

13 项功能需求按迭代交付：迭代一交付 FR-01 与 FR-04 的数据结构基础；迭代二交付 FR-02～FR-11；迭代三交付 FR-12、FR-13。

## 4 非功能性需求

| 编号 | 类别 | 需求描述（可验证） | 度量方式 |
| --- | --- | --- | --- |
| NFR-01 | 性能 | 核心查询响应 ≤2s（95 分位，5 万册/50 万条借阅数据量） | 压测 200 次取 P95 |
| NFR-02 | 性能 | ≥50 并发用户，错误率 <1% | 50 线程压测 5 分钟 |
| NFR-03 | 容量 | 5 万册图书、1 万名读者、50 万条借阅记录，查询不全表扫描 | EXPLAIN QUERY PLAN 检查索引 |
| NFR-04 | 安全性 | 口令 PBKDF2-HMAC-SHA256（120000 轮、16 字节随机盐），恒定时间比较 | 检查库中字段格式 + 单元测试 |
| NFR-05 | 安全性 | 失败 5 次锁定 15 分钟；会话 30 分钟过期；Cookie HttpOnly + SameSite=Lax | 用例覆盖锁定与过期 |
| NFR-06 | 安全性 | 按角色的接口级访问控制，越权返回 403 | 三角色逐一调用接口核对响应码 |
| NFR-07 | 日志与审计 | 关键操作留存日志（操作人、时间、IP、结果），保留 ≥180 天 | 抽查 business.log 与 sys_audit_log |
| NFR-08 | 易用性 | 主要业务 3 次点击内到达；表单错误定位到字段 | 界面走查 + 边界用例 |
| NFR-09 | 可靠性 | 单请求异常不影响进程；异常统一返回 code/msg；可用率 99% | 注入非法 JSON、超长参数 |
| NFR-10 | 可维护性 | controller/service/dao/db 分层；单文件 ≤400 行；关键规则有注释 | 代码走查 + 行数脚本 |
| NFR-11 | 可移植性 | 仅依赖标准库，Windows/Linux 一条命令启动 | 两套环境启动验证 |
| NFR-12 | 兼容性 | Chrome/Edge/Firefox 最近两版，1366×768 起 | 三款浏览器实测 |

课程底线指标映射：核心查询 ≤2s → NFR-01；≥50 并发 → NFR-02；口令加密 → NFR-04；关键操作日志 → NFR-07。
