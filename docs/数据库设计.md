| 项目 | 内容 |
| --- | --- |
| 文档编号 | LIB-DB-001 |
| 版本 | V1.0 |
| 编制 | 陈俊年 |
| 数据库 | SQLite 3.45（单文件，UTF-8） |
| 建表脚本 | `src/db/schema.sql` |
| 初始化脚本 | `src/db/init_db.py` |
| 建模方法 | 概念模型（E-R）→ 逻辑模型（关系模式）→ 物理模型（SQLite 建表语句） |

## 1 设计原则

1. 账号统一：三类角色（读者、图书馆管理员、审核统计管理员）共用 `sys_user` 一张账号表，用 `role` 字段区分，避免三套登录逻辑；只有读者的业务属性（借阅上限、信用分）拆到 `reader_profile`。
2. 书目与复本分离：`book` 存书目信息（一种书一条），`book_copy` 存实体复本（每本一条，条码唯一）。同一本《数据结构》有 5 册时，就有 5 条复本记录，借阅记录指向复本而不是书目，这样才能表达"哪一册被谁借走"。
3. 业务留痕：借阅、罚款、预约都不做物理删除，靠 `status` 字段表达状态流转；罚款减免、账号审核等关键操作写入 `sys_audit_log`。
4. 约束下沉：能用数据库约束表达的规则就不放到代码里，如角色、状态取值用 `CHECK`，唯一性用唯一索引，引用完整性用外键（并显式开启 `PRAGMA foreign_keys`）。
5. 时间统一：所有时间字段使用 `TEXT` 存储 `YYYY-MM-DD HH:MM:SS` 格式的本地时间字符串，便于排序与比较，也便于直接在 SQLite 命令行查看。

## 2 E-R 模型文字描述

### 2.1 实体与主要属性

| 编号 | 实体 | 主要属性 | 说明 |
| --- | --- | --- | --- |
| E1 | 用户账号（sys_user） | 用户ID（主键）、登录名、口令散列、真实姓名、角色、状态、手机号、失败次数、锁定截止、最后登录时间 | 三类角色共用的身份实体 |
| E2 | 读者档案（reader_profile） | 读者ID（主键）、用户ID（外键）、读者证号、读者类型、可借上限、信用分 | 用户的子类型实体，一张账号最多一条档案 |
| E3 | 图书分类（book_category） | 分类ID（主键）、分类名称、上级分类ID（自引用）、排序号 | 支持两级分类 |
| E4 | 书目（book） | 书目ID（主键）、ISBN、书名、作者、出版社、出版年、分类ID、单价、总册数、可借册数、书目状态 | 一种书一条记录 |
| E5 | 馆藏复本（book_copy） | 复本ID（主键）、书目ID（外键）、条码、馆藏位置、复本状态 | 实体书，条码唯一 |
| E6 | 借阅记录（borrow_record） | 记录ID（主键）、读者ID、复本ID、借出时间、应还时间、归还时间、续借次数、记录状态、经办人 | 一条记录对应一次借阅 |
| E7 | 预约（reservation） | 预约ID（主键）、读者ID、书目ID、排队号、预约状态、到书时间、失效时间、履约时间 | 按书目预约，不指定复本 |
| E8 | 罚款单（fine_record） | 罚款ID（主键）、借阅记录ID、读者ID、逾期天数、金额、状态、缴纳时间、经办人 | 一条逾期记录最多一张罚款单 |
| E9 | 业务日志（sys_audit_log） | 日志ID（主键）、用户ID、动作、操作对象、详情、IP、结果、时间 | 只追加不修改 |
| E10 | 会话（sys_session） | 令牌（主键）、用户ID、创建时间、过期时间 | 登录后签发，过期即失效 |
| E11 | 通知（notice） | 通知ID（主键）、用户ID、标题、内容、类型、已读标记、时间 | 到期提醒、到书通知、公告 |

### 2.2 联系与基数

| 联系 | 参与实体 | 基数 | 说明 |
| --- | --- | --- | --- |
| 拥有档案 | 用户账号 — 读者档案 | 1 : 0..1 | 只有角色为读者的账号才有档案；档案随账号级联删除 |
| 归属分类 | 图书分类 — 书目 | 1 : 0..* | 一个分类下有多本书；分类可自引用形成父子层级 |
| 包含复本 | 书目 — 馆藏复本 | 1 : 1..* | 一种书至少一册复本，复本随书目删除而删除 |
| 借阅读者 | 读者档案 — 借阅记录 | 1 : 0..* | 一名读者可以有多条在借或历史记录 |
| 借出复本 | 馆藏复本 — 借阅记录 | 1 : 0..* | 一册复本历史上被多次借出，同一时刻最多一条未归还记录 |
| 产生罚款 | 借阅记录 — 罚款单 | 1 : 0..1 | 只有逾期归还才产生罚款单；减免后状态置为已减免，记录保留 |
| 预约书目 | 读者档案 — 书目 | 0..* : 0..* | 通过 `reservation` 关联，同一读者对同一书目同时最多一条有效预约 |
| 触发通知 | 用户账号 — 通知 | 1 : 0..* | 通知可以面向单个用户，也可以面向全体（`user_id` 为空表示公告） |
| 持有会话 | 用户账号 — 会话 | 1 : 0..* | 同一账号允许多端登录，各自持有独立令牌 |
| 记录日志 | 用户账号 — 业务日志 | 1 : 0..* | 日志中的 `user_id` 允许为空（如登录失败时尚未确定用户） |

### 2.3 E-R 图绘制说明

E-R 图在迭代二随第3章一并提交。绘图时按下列约定，保证与本文档一致：

- 矩形表示实体，菱形表示联系，椭圆表示属性（只画主键、外键与关键业务属性，其余属性列在实体旁注中）；
- 联系线上标注基数，1 写在靠近"一"的一方，`0..*` 写在靠近"多"的一方；
- `用户账号 — 读者档案` 画成 1:1 的子类型联系，标注 `{角色=读者}`；
- `借阅记录 — 罚款单` 画成 1:0..1，标注条件 `{逾期天数>0}`；
- 图中只画 E1～E8 八个业务实体，E9～E11 作为支撑实体画在右下角虚线框内，标注"支撑实体"。

## 3 数据表与字段

### 3.1 sys_user（用户账号）

| 字段 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| user_id | INTEGER | 主键，自增 | 用户ID |
| username | TEXT | 非空，唯一索引 `uk_user_username` | 登录名，读者注册时与读者证号一致 |
| password_hash | TEXT | 非空 | `pbkdf2_sha256$轮数$盐$散列` 格式 |
| real_name | TEXT | 非空 | 真实姓名 |
| role | TEXT | 非空，默认 `READER`，`CHECK` 取值 `READER/LIBRARIAN/AUDITOR` | 角色 |
| status | TEXT | 非空，默认 `ACTIVE`，`CHECK` 取值 `ACTIVE/FROZEN/PENDING` | 账号状态 |
| phone | TEXT | 可空 | 手机号 |
| fail_count | INTEGER | 非空，默认 0 | 连续登录失败次数 |
| lock_until | TEXT | 可空 | 锁定截止时间，为空表示未锁定 |
| last_login_at | TEXT | 可空 | 最后登录时间 |
| created_at / updated_at | TEXT | 非空 | 创建与更新时间 |

索引：`uk_user_username`（唯一）、`idx_user_role`。

## 4 状态字典

| 字典 | 取值 | 流转说明 |
| --- | --- | --- |
| 账号状态 `sys_user.status` | `PENDING` 待审核 → `ACTIVE` 正常 → `FROZEN` 冻结 | 迭代一为便于联调，自助注册后直接置为 `ACTIVE`；迭代二接入账号审核后改为先置 `PENDING`。`FROZEN` 账号禁止登录 |
| 复本状态 `book_copy.status` | `AVAILABLE` 在架 → `BORROWED` 借出 → `AVAILABLE`；`RESERVED` 预约保留；`LOST`/`REPAIR` 人工登记 | 借还业务自动流转，`BORROWED` 不允许人工直接修改 |
| 借阅状态 `borrow_record.status` | `BORROWED` → `OVERDUE`（到期未还）→ `RETURNED` | 归还时按 `return_at` 是否超过 `due_at` 判定是否生成罚款 |
| 预约状态 `reservation.status` | `QUEUING` → `READY`（到书保留）→ `FULFILLED` 取书；`EXPIRED` 超期失效；`CANCELLED` 读者取消 | 失效后排队号顺延给下一位 |
| 罚款状态 `fine_record.status` | `UNPAID` → `PAID` 已缴 / `WAIVED` 已减免 | 减免须审核统计管理员审批并写日志 |

## 5 建表与初始化

```bash
# 1) 建库并建表（重复执行不会报错，脚本内使用 IF NOT EXISTS）
python -m src.db.init_db

# 2) 生成的数据库文件
data/library.db

# 3) 演示账号（迭代一仅用于登录联调，口令均为 8 位）
libadmin / lib123456        图书馆管理员
auditor  / audit123456      审核统计管理员
reader01 / reader123456     读者（学生）
```

初始化脚本会按顺序执行 `schema.sql`、写入 3 个演示账号（口令经 PBKDF2 散列后入库）与 3 个示例图书分类，不写入任何模拟借阅数据，避免与迭代二的业务测试数据混淆。
